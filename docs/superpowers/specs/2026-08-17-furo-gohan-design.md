# 風呂予約・白米投票システム 設計書

作成日 2026-08-17

## 目的

インターンの共同生活期間中、風呂の順番と白米を炊く量を決める手間をなくす。風呂は先着順の枠予約、白米は食事ごとの挙手で頭数を集める。LAN 内に置いた Raspberry Pi の上で動かし、参加者が各自のスマートフォンから開く。

## 対象期間

滞在は 2026-08-17 の晩に始まり、2026-08-28 の朝に終わる。この境界により、機能ごとに扱う日付の範囲が異なる。

朝ごはんだけ 1 日遅れて始まる。8/18 の朝ごはんは、その投票窓である 8/17 の 18:00 から 22:00 が過ぎたあとに決まったため、対象から外す。

| 対象 | 開始 | 終了 |
| --- | --- | --- |
| 夜風呂 | 2026-08-17 | 2026-08-27 |
| 朝風呂 | 2026-08-18 | 2026-08-28 |
| 朝ごはん | 2026-08-19 | 2026-08-28 |
| 晩ごはん | 2026-08-18 | 2026-08-27 |

範囲は設定値として一箇所にまとめる。日程が動いた場合は設定を書き換えるだけで対応できる。範囲外の日付を開いた場合、表やカードを描画せず「対象期間外」と表示する。

## 利用者と識別

参加者は名簿に登録された数名から十数名を想定する。パスワードは設けない。LAN 内からしか到達できず、参加者は同じ屋根の下にいるため、他人になりすます動機がない。

初回アクセス時に名前の選択画面を表示し、選んだ結果を有効期限 30 日の Cookie に保存する。以降は自分の名前で操作できる。画面上部に現在の名前と変更用のリンクを常に置く。

名簿は `/members` で追加と非表示ができる。認証は設けない。非表示にした利用者の既存の予約と投票は残す。

## 風呂の予約

### 枠

浴室は 2 つある。浴槽のない `shower`（表示名「風呂」）と、浴槽のある `tub`（表示名「風呂（浴槽付き）」）である。

枠の長さは浴室ごとに違う。浴槽付きは 20 分、浴槽なしは 15 分とする。湯を張る手間の分だけ浴槽付きを長く取る。

時間帯は朝と夜の 2 区分を持つ。朝 (`morning`) は 06:00 から 08:00 まで、夜 (`night`) は 19:00 から 24:00 までである。

夜は終了時刻より早く受付を打ち切り、入浴を始められるのは 23:00 までとする。深夜の入浴を止めるための制限で、23:00 に始まった枠は 24:00 より前に終わる。

| 浴室 | 朝 | 夜 |
| --- | --- | --- |
| 風呂（15 分） | 06:00 から 07:45 までの 8 枠 | 19:00 から 23:00 までの 17 枠 |
| 風呂（浴槽付き、20 分） | 06:00 から 07:40 までの 6 枠 | 19:00 から 23:00 までの 13 枠 |

枠はデータベースに持たず、区分の時間帯と浴室ごとの刻み幅から生成する。

刻み幅が違うため、2 つの浴室で時刻の行が揃わない。1 つの表に並べず、浴室ごとに独立した列として横に並べる。

### 規則

- 予約できるのは今日と明日の枠に限る。それより先は選べない。
- 開始時刻を過ぎた枠は予約できない。判定はサーバの時刻で行う。
- 1 人が同じ日の同じ区分で持てる枠は 1 つまで。朝に 1 枠、夜に 1 枠まで取れる。浴室が違っても 2 枠は取れない。
- 自分の予約はいつでも取り消せる。開始時刻を過ぎた予約も取り消せる。取り消すとその区分の枠が空き、同じ日でも別の枠を取り直せる。ただし開始時刻を過ぎた枠は誰も予約できないため、空きのまま残る。
- 他人の予約は取り消せない。

### 先着順の保証

同じ枠を 2 人が同時に押す状況は必ず起きる。これをアプリケーション側の「空きを確認してから書き込む」手順で捌くと、確認と書き込みの間に別の要求が割り込む。判定はデータベースの一意制約に任せる。

`bath_reservations` に `UNIQUE(date, room, slot)` を置き、書き込みが成功した側だけを予約とする。制約違反を受け取った側には「この枠はちょうど埋まりました」と表示し、最新の表に戻す。1 人 1 枠の制限も同じ仕組みで、`UNIQUE(date, section, member_id)` が守る。

制約違反を受け取った後、どちらの制約に触れたかを判定してから文言を選ぶ。すでに枠を持っていた場合は、その枠の時刻と浴室まで示す。

## 白米の投票

### 投票の対象

朝ごはんと晩ごはんのそれぞれについて、白米が要る人を数える。要る人だけが挙手し、押していない状態を「要らない」として扱う。「要らない」を明示するボタンは置かない。

### 受付の窓

| 対象 | 受付開始 | 締切 |
| --- | --- | --- |
| D 日の朝ごはん | D-1 日 18:00 | D-1 日 22:00 |
| D 日の晩ごはん | D 日 09:00 | D 日 18:00 |

朝の分は前夜のうちに締め切り、晩の分は当日の夕方に締め切る。締切時刻ちょうどは締切済として扱う。受付中の条件は「受付開始時刻以上、かつ締切時刻未満」である。

窓の判定はサーバの時刻だけで行う。締切後に届いた投票と取り消しは拒否する。

### 表示

食事を時系列に並べ、最大 4 件を表示する。締切が未来の食事のうち先頭 3 件と、直近で締め切った 1 件である。各カードは対象の日付、朝か晩か、状態、人数を持つ。

状態は 3 つある。受付前のカードには受付開始時刻を示す。受付中のカードには締切時刻と挙手ボタンを置く。締切済のカードには人数だけを残す。

挙手ボタンは中央に 1 つ置く。押していない状態では「いる」と表示し、押すと「いる ✓」に変わって、その下に取り消し用のボタンが現れる。取り消しは受付中に限る。

人数は「いる 5 人 / 登録 8 人」と分母を添えて示す。返事がまだ 3 人分ないのか、3 人が要らないのかを炊く人が判断できる。個人名は出さない。

## データモデル

SQLite を用いる。WAL モードで開き、外部キー制約を有効にする。

```sql
CREATE TABLE members (
  id         INTEGER PRIMARY KEY,
  name       TEXT    NOT NULL UNIQUE,
  active     INTEGER NOT NULL DEFAULT 1,
  created_at TEXT    NOT NULL
);

CREATE TABLE bath_reservations (
  id         INTEGER PRIMARY KEY,
  date       TEXT    NOT NULL,
  section    TEXT    NOT NULL CHECK (section IN ('morning', 'night')),
  room       TEXT    NOT NULL CHECK (room IN ('shower', 'tub')),
  slot       TEXT    NOT NULL,
  member_id  INTEGER NOT NULL REFERENCES members(id),
  created_at TEXT    NOT NULL,
  UNIQUE (date, room, slot),
  UNIQUE (date, section, member_id)
);

CREATE TABLE rice_votes (
  id         INTEGER PRIMARY KEY,
  date       TEXT    NOT NULL,
  meal       TEXT    NOT NULL CHECK (meal IN ('breakfast', 'dinner')),
  member_id  INTEGER NOT NULL REFERENCES members(id),
  created_at TEXT    NOT NULL,
  UNIQUE (date, meal, member_id)
);
```

日付は `YYYY-MM-DD`、枠の開始時刻は `HH:MM` の文字列で持つ。時刻は Asia/Tokyo で解釈する。投票の取り消しは行の削除で表す。

## 画面と経路

| 経路 | 種別 | 内容 |
| --- | --- | --- |
| `/` | GET | `/bath` へ転送する |
| `/select` | GET, POST | 名前を選び Cookie に保存する |
| `/bath` | GET | 風呂タブ。`?date=` で今日と明日を切り替える |
| `/bath/reserve` | POST | 予約し、元の日付へ転送する |
| `/bath/cancel` | POST | 自分の予約を取り消す |
| `/meals` | GET | ごはんタブ |
| `/meals/vote` | POST | 挙手する |
| `/meals/unvote` | POST | 挙手を取り消す |
| `/members` | GET, POST | 名簿の追加と非表示 |
| `/fragment/bath` | GET | 風呂の表だけを返す。自動更新に使う |
| `/fragment/meals` | GET | ごはんのカードだけを返す。自動更新に使う |

操作はすべて通常のフォーム送信で行い、書き込み後は転送して再送信を防ぐ。JavaScript を切っていても予約と投票ができる。JavaScript が動く環境では 10 秒ごとに断片を取得して表を差し替え、他人の操作が反映される。

エラーは Flask のフラッシュメッセージで画面上部に出す。署名鍵はデータ用ディレクトリに初回起動時に生成して保存する。

## 見た目

背景は白、文字は濃い灰、罫線は薄い灰とする。予約済みの枠は薄い灰の背景を敷き、自分の予約だけ枠線を濃くする。フォントは端末の既定を使い、装飾は加えない。

画面に文章を置かない。使い方の説明も、動作の断り書きも書かない。出すのは見出し、時刻、名前、人数、ボタン、そして操作の結果として出るエラーだけとする。状態を示す短い語（「締切」「対象期間外です」など）は文章ではないため残す。

スマートフォンの縦画面を基準に組み、指で押せる高さを枠のボタンに与える。横幅は 1 画面に収め、横スクロールを起こさない。

## エラー処理

| 状況 | 応答 |
| --- | --- |
| 枠が同時に埋まった | 「この枠はちょうど埋まりました」 |
| すでにその区分の枠を持っている | 「夜の枠は 20:00 の風呂を予約済みです。取り消してから選んでください」 |
| 開始時刻を過ぎた枠を押した | 「その枠は始まっています」 |
| 対象期間外または今日と明日以外の日付 | 「その日は予約できません」 |
| 他人の予約を取り消そうとした | 「他の人の予約は取り消せません」 |
| 受付前または締切後の投票 | 「受付時間外です」 |
| 名前が未選択 | 名前の選択画面へ転送する |

いずれも状態を変えず、直前の画面に最新の内容を添えて戻す。

## 実行環境

Python 3.11 以上、Flask、SQLite を用いる。外部との通信は行わない。

`0.0.0.0:8080` で待ち受け、LAN 内からのみ到達できるようにする。Raspberry Pi では systemd のサービスとして常駐させ、起動時に自動で立ち上げる。時刻帯は Asia/Tokyo に固定する。

Pi への配置は `deploy.sh` にまとめる。SSH でファイルを送り、仮想環境を作り、systemd の設定を置いて起動するまでを一度に行う。同じ手順を繰り返し流しても結果が変わらないようにし、データベースと設定ファイルは上書きしない。

現在時刻の取得は 1 箇所の関数にまとめ、テストから差し替えられるようにする。期間や窓を判定する関数は現在時刻を引数で受け取る純粋な関数として書き、データベースに触れない。

## テスト

pytest を用いる。

- 枠の生成。浴室ごとに刻み幅が変わり、朝は 8 枠と 6 枠、夜は 17 枠と 13 枠になること。
- 夜の枠が 23:00 で打ち切られ、それより後の開始時刻がどちらの浴室でも通らないこと。
- 対象期間の判定。2026-08-17 の朝、2026-08-28 の夜、範囲外の日付が除かれること。
- 予約が成立し、表に反映されること。
- 同じ枠へ複数のスレッドから同時に要求を出したとき、成功が 1 件だけになること。
- 同じ日の同じ区分で 2 枠目を取ろうとすると拒否され、朝と夜で 1 枠ずつは取れること。
- 開始時刻を過ぎた枠が予約できないこと。
- 自分の予約は取り消せ、他人の予約は取り消せないこと。
- 投票の窓。受付開始時刻ちょうど、締切時刻ちょうど、窓の外での挙手と取り消しの可否。
- 締切後の投票が拒否され、人数が変わらないこと。
- ごはんタブに並ぶ食事が、締切の近い順に最大 4 件で、締切済が 1 件だけ残ること。

## 対象外

食事の当番や献立、風呂の掃除当番、外部への通知、外部からの接続、利用者ごとの権限は扱わない。画面に出すのは風呂の予約、白米の投票、名簿の登録だけとする。
